# Per-project cell timeout for the compatibility matrix, in seconds.
#
#   <project path>   <seconds>      # 0 = no limit
#
# Only consulted when a caller sets CELL_TIMEOUT (run-compat-matrix does, from
# MATRIX_CELL_TIMEOUT). A project listed here overrides that default.
#
# Why a limit at all: on 2026-10-07 a single cell ran for 14.2 hours while the
# matrix made no other progress, and the whole run was still unfinished a day
# later. One runaway cell must cost one cell, not the window.
#
# its-3 was exempt (0 = no limit) because the suite legitimately needed hours:
# 2790s to 51159s across variants. That range was dominated by the Maven 4
# columns, and those are now blocked for this project in project-variants.txt,
# because the 3.x harness drives Maven through MavenCli while Maven 4 uses
# MavenCling. What remains is the 3.x columns, whose measured worst case is
# 2790s (46 min), so 7200 leaves 2.6x headroom.
#
# An exemption is no longer the safe choice either: the cell holds the matrix
# lock, and a run-compat-matrix that finds the lock held exits 0 SILENTLY. One
# hung its-3 cell would therefore not just cost its own window, it would make
# the next scheduled matrix run disappear without a trace.
core/3.x/its-3   7200
