# Maven distributions to materialise for the compatibility matrix.
#
#   <version>   <project path under MAVEN_PROJECTS_DIR>   [branch]
#
# <version> is either a literal version or "auto", meaning "read it from the
# project's POM" (from origin/<branch> when a branch is given). SNAPSHOT lines
# use "auto" so a release that advances the branch is picked up without a
# manifest edit -- see variants.txt for why pinning them went wrong.
#
# A third column names a branch the manifest does NOT check out. The repo
# manifest gives one branch per project, so a second active line of the same
# repository needs a worktree; build-maven-lines materialises and builds it
# under maven-lines/<version>.
#
# The distribution archive is a by-product of the normal nightly build -- the
# listed projects are part of the 125 the pipeline builds anyway -- so nothing
# here triggers a build of its own. install-maven-dist only unpacks and links,
# and only when the source commit actually moved.
#
# 4.0.x is named after the BRANCH, not after the version its build reports
# (4.0.0-SNAPSHOT). That originally avoided a collision with the dpv-* spike
# variants, which carried 4.0.0-SNAPSHOT too and would have had their symlink
# silently re-pointed at this plain build. The spike is gone (see
# variants.txt), so the reason is historical -- the name stays because
# renaming it would mean re-materialising a working distribution for cosmetics.
#
# master is listed under the version it reports, 4.1.0-SNAPSHOT: there is no
# "4.1.x" branch to name it after.
auto             core/maven-4.0.x
auto             core/maven
auto             core/3.x/maven-3
auto             core/3.x/maven-3   maven-3.9.x
