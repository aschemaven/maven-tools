# Compat-matrix machine roles (Phase 5).
#
# Maps a host short-name (output of `hostname -s`) to a role that controls
# whether compat-tick may run heavy IT builds:
#
#   controller  the daily-work machine: heavy builds ONLY in the nightly
#               window AND when the machine is idle (no recent HID input).
#               The cheap brain (sync + change detection + render) always runs.
#   runner      a dedicated build box: builds freely whenever the tick fires.
#
# Format:  <host-short-name>   <role>
# Lines starting with # and blank lines are ignored.
# Override at runtime with COMPAT_ROLE=controller|runner.
# Unknown hosts default to "controller" (the polite choice).

godecane          controller
# intel-macbook   runner
# linux-laptop    runner
# The dedicated builder, so "runner": it builds whenever the tick fires.
#
# It was a "controller" with its window shifted to 11-19 (NIGHTLY_START /
# NIGHTLY_END in the launchd plist there), on the assumption that the
# jQAssistant nightly occupies 03:00 to about 15:00. That has not been true
# for a while -- measured over 2026-10-16..18 the nightly runs 21:00 to about
# 04:30 -- so the shifted window cost the machine the sixteen hours outside
# 11-19 while nothing else wanted them. On the night of 10-21, with the
# nightly dead, the matrix covered more cells than in the whole week before.
#
# Yielding to the nightly does not depend on the role: should_build() checks
# the .jqa-nightly.lock BEFORE it looks at the role, so a runner stands aside
# exactly as a controller does. What the role drops is the time window and the
# HID-idle test, neither of which means anything on a box nobody types on
# (measured idle there: 5.1 days).
#
# The window variables stay in the plist but are now unread. They apply again
# the moment this row says "controller" or COMPAT_ROLE overrides it.
godestorm         runner
